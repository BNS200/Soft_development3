# Soft_development3

## 1.Постановка задачи

Разработать приложение для печати графиков, используя принципы Dependency Injection (DI) и Inversion of Control (IoC).

**Исходные данные:** 
1. Готовая реализация IOC-контейнера. 
2. MVC("модель-вид-контроллер") модель, позволяющей отображать файловую системы машины.

**Основные требования:**

1. Использование принципа внедрения зависимости (Dependency Injection)
2. Реализация внедрения зависимости с помощью IoC контейнера
3. Возможность добавления новых типов графиков (графики отличаются видом и данными)
4. Возможность изменения визуального стиля графиков (цветной, черно-белый)

## 2. Предлагаемое решение

### 2.1 Общая архитектура

В основе разработанного решения лежит архитектура приложения, построенная с использованием паттернов IoC (Inversion of Control) и Dependency Injection, 
что обеспечивает снижение связанности компонентов. Применение паттернов "Адаптер" и принципов Dependency Injection и Open/Closed позволяет легко добавлять 
новые источники данных (JSON, SQLite), типы графиков (столбчатая, круговая) и стили печати (цветной, черно-белый) без изменения существующего кода. 
Использование концепции MVC для файлового системы обеспечивает разделение данных, отображения и логики управления. Реализованный IoC контейнер с поддержкой 
именованной регистрации и шаблонов управляет жизненным циклом объектов и автоматически разрешает зависимости, что делает систему гибкой и расширяемой.

### 2.2 Паттерн адаптер

**Адаптер** — это структурный паттерн проектирования,который позволяет объектам с несовместимыми интерфейсами работать вместе.

### 2.3 Концепция MVC

Основная задача концепции MVC – разделить части программы, отвечающие за хранение и 
доступ к данным, их отображение и взаимодействие с пользователем на три отдельных модуля,
разработка которых относительно независима.

### 2.4 Структура классов

#### Класс DataPoint

**Назначение:** структура для хранения одной точки данных графика.

**Поля:**
- `date` – дата и время (QDateTime)
- `value` – числовое значение (double)
- `label` – текстовая подпись (QString)

**Основные методы:**
- `DataPoint()` – конструктор по умолчанию
- `DataPoint(date, value, label)` – конструктор с параметрами

---

#### Интерфейс IDataProvider

**Назначение:** абстрактный класс для всех источников данных.

**Основные методы:**
- `getData()` – чисто виртуальный метод, возвращает набор данных (DataSet)
- `getSourceName()` – возвращает имя источника данных
- `getDescription()` – возвращает описание источника

---

#### Интерфейс IChartRenderer

**Назначение:** абстрактный класс для всех рендереров графиков.

**Основные методы:**
- `createChart(data)` – чисто виртуальный метод, создает и возвращает график
- `getChartType()` – возвращает тип графика
- `customizeChart(chart)` – настройка внешнего вида графика

---

#### Интерфейс IPrintStyle

**Назначение:** абстрактный класс для всех стилей печати.

**Основные методы:**
- `configurePrinter(printer)` – настройка принтера для печати в PDF (цвет/чб, разрешение)
- `configurePainter(painter)` – настройка рисовальщика
- `customizeChart(chart)` – настройка внешнего вида графика
- `getStyleName()` – возвращает название стиля

---

#### Класс JSONDataAdapter

**Назначение:** адаптер для чтения данных из JSON файлов. Наследует `IDataProvider`.

**Основные методы:**
- `getData()` – читает JSON файл, парсит данные, возвращает DataSet
- `getSourceName()` – возвращает "JSON File"
- `getDescription()` – возвращает путь к файлу

**Поля:**
- `m_filePath` – путь к JSON файлу
- `m_dateFormat` – формат даты

---

#### Класс SQLiteAdapter

**Назначение:** адаптер для чтения данных из SQLite баз данных. Наследует `IDataProvider`.

**Основные методы:**
- `getData()` – выполняет SQL запрос, возвращает DataSet
- `getTableList(filePath)` – статический метод, возвращает список таблиц
- `getSourceName()` – возвращает "SQLite Database"
- `getDescription()` – возвращает путь к БД и имя таблицы

**Поля:**
- `m_dbPath` – путь к файлу БД
- `m_tableName` – имя таблицы
- `m_dateColumn` – имя колонки с датой
- `m_valueColumn` – имя колонки со значением
- `m_dateFormat` – формат даты

---

#### Класс BarChartRenderer

**Назначение:** рендерер столбчатой диаграммы. Наследует `IChartRenderer`.

**Основные методы:**
- `createChart(data)` – создает столбчатую диаграмму
- `getChartType()` – возвращает "Bar Chart"
- `customizeChart(chart)` – настройка темы и легенды

---

#### Класс PieChartRenderer

**Назначение:** рендерер круговой диаграммы. Наследует `IChartRenderer`.

**Основные методы:**
- `createChart(data)` – создает круговую диаграмму
- `getChartType()` – возвращает "Pie Chart"
- `customizeChart(chart)` – настройка темы и легенды

---

#### Класс ColorStyle

**Назначение:** цветной стиль печати. Наследует `IPrintStyle`.

**Основные методы:**
- `configurePrinter(printer)` – устанавливает цветной режим
- `configurePainter(painter)` – настройка отрисовки
- `customizeChart(chart)` – устанавливает светлую тему и легенду
- `getStyleName()` – возвращает "Color"

---

#### Класс GrayStyle

**Назначение:** черно-белый стиль печати. Наследует `IPrintStyle`.

**Основные методы:**
- `configurePrinter(printer)` – устанавливает черно-белый режим
- `configurePainter(painter)` – настройка отрисовки
- `customizeChart(chart)` – перекрашивает серии в серые тона
- `getStyleName()` – возвращает "Gray"

---

#### Класс IOCContainer

**Назначение:** контейнер для управления зависимостями.

**Основные методы:**
- `RegisterInstance<T>(name, obj)` – регистрация готового объекта (синглтон)
- `RegisterFactory<TInterface, TConcrete, Args...>(name)` – регистрация фабрики, вызывающей конструктор
- `RegisterFunctor<TInterface, Args...>(name, func)` – регистрация пользовательской функции создания
- `GetObject<T>(name)` – получение объекта из контейнера

**Поля:**
- `m_factories` – map для хранения фабрик
- `s_nextTypeId` – статический счетчик ID типов

---

#### Класс MainWindow

**Назначение:** главное окно приложения, контроллер MVC. Управляет выбором файлов, загрузкой данных, отображением графиков и печатью.

**Основные методы:**
- `loadDataFromFile(filePath)` – загрузка данных из JSON или SQLite
- `updateChart()` – обновление отображения графика
- `switchToChartMode()` – переключение в режим отображения графика
- `onFileSelectedForChart(index)` – обработчик выбора файла
- `on_selectionChangedSlot(selected, deselected)` – обработчик выбора папки (MVC Controller)
- `onChartTypeChanged(index)` – обработчик смены типа графика
- `onStyleChanged(index)` – обработчик смены стиля печати
- `onPrintButtonClicked()` – обработчик печати в PDF
- `onExitChartMode()` – выход из режима графика
- `registerDependencies()` – регистрация зависимостей в контейнере

**Поля:**
- `m_container` – экземпляр IoC контейнера
- `m_currentData` – текущий набор данных
- `m_currentRenderer` – текущий рендерер графика
- `m_currentStyle` – текущий стиль печати
- `leftPartModel`, `rightPartModel` – модели файловой системы (MVC)
- `treeView`, `tableView` – представления файловой системы (MVC)
- `m_splitter` – разделитель
- `m_chartView` – виджет отображения графика
- `m_chartWidget` – виджет с элементами управления графиком
- `m_isChartMode` – флаг режима графика
- `m_savedSizeSplitter` - сохраненные размеры сплиттера для восстановления
- `m_chartView` - виджет для отображения графика 
- `m_chartTypeCombo` - выпадающий список для выбора типа графика 
- `m_styleCombo` - выпадающий список для выбора стиля печати 
- `m_statusLabel` - метка для отображения статуса загрузки 
- `m_exitButton` - кнопка выхода из режима графика 
- `m_printButton` - кнопка печати в PDF

## 3. Инструкция пользователя
### 3.1 Сборка программы

**Требования для сборки:**
- Qt: версия 5 или 6 
- CMake: версия 3.1 или выше
- Компилятор: с поддержкой C++17

**Инструкция по сборке (macOS/Linux):**
- Настройка проекта: `cmake -B build -S .`
- Компиляция проекта: `cmake --build build`
- Запуск программы: `./build/project_name`
